# Markdown Link Policy Rule

## 원칙

**모든 마크다운 파일에서 경로·파일을 참조할 때 반드시 클릭 가능한 상대 링크로 작성한다.**

douzone-forge는 모듈·프로젝트·참조자료·세션 간 교차 참조가 매우 많다. 텍스트 단독 표기는 클릭 불가하고, 리팩터링 시 끊어진 링크를 검출할 수 없어 맥락 단절을 유발한다.

## 기본 규칙

1. 경로를 텍스트로만 표기하지 않는다 — 항상 `[표시텍스트](상대경로)` 형식
2. 상대 경로는 현재 파일 위치 기준으로 작성한다
3. 코드블록(```` ``` ````) 안의 경로나 폴더 구조 다이어그램은 예외 (링크 불필요)
4. **설계서 파일명(PDF, PPTX 등)도 반드시 클릭 가능한 마크다운 링크로 작성한다** — 텍스트 단독 표기 금지

## URL 인코딩 규칙 (필수)

파일명·경로에 특수문자가 포함된 경우 반드시 URL 인코딩 처리한다.

| 원문자 | 인코딩 | 사례 |
|--------|--------|------|
| `[` | `%5B` | `[CRM]` → `%5BCRM%5D` |
| `]` | `%5D` | |
| `(` | `%28` | `법무관리(LTE)` → `법무관리%28LTE%29` |
| `)` | `%29` | |
| 공백 ` ` | `%20` | `기능 개선` → `기능%20개선` |

> 괄호 인코딩 보충 (2026-08-13) — CommonMark 규격은 **균형 잡힌 괄호**를 목적지 안에서 허용하므로 `법무관리(LTE)` 는 표준 파서에서 끊기지 않는다. 그래도 인코딩을 의무로 두는 이유는 뷰어·URL 처리 구현이 갈리기 때문이다. **다만 「괄호가 있으니 깨졌다」고 단정하지 말 것** — 판정은 반드시 공식 검사기로 한다(정규식은 CommonMark 파서가 아니다). 경위: `참고자료/리포트/2026-08-11-마크다운-링크-문법사고-실측재판정.md`(forge)

## 적용 범위

- douzone-forge 워크스페이스 전체 `*.md` 파일
- `프로젝트/`, `context/`, `tasks/`, `history/`, `문서/INDEX.md`, 스킬 SKILL.md 모두 포함
- 코드블록 내부 경로 및 폴더 구조 트리는 예외

### ⛔ 예외 — 플러그인 자산이 워크스페이스를 가리킬 때 (2026-08-13 신설)

**플러그인(`_plugin/douzone-forge/`) 안의 문서가 워크스페이스 파일을 가리킬 때는 링크로 만들지 않는다.**

플러그인은 `~/.claude/plugins/cache/…` 에 설치되고 워크스페이스는 사용자마다 다른 곳에 있어, **어떤 상대경로도 배포본에서 성립하지 않는다**(실측: 154건 중 해석 성공 0건).

```markdown
✅ 단일 출처(SSoT) = `규칙/프로세스/API참조-체계-표준.md`(forge)
❌ [`API참조-체계-표준.md`](../../../규칙/프로세스/API참조-체계-표준.md)
❌ [`API참조-체계-표준.md`](../../../douzone-forge/규칙/프로세스/API참조-체계-표준.md)
```

- 경로는 **워크스페이스 루트 기준** + 백틱, 뒤에 좌표 마커 `(forge)`
- 플러그인 **안**을 가리키는 링크는 종전대로 상대 링크를 쓴다
- `skills/*/templates/`·`skills/*/assets/` 는 복사 후 워크스페이스에 놓이는 전제라 예외

정본: `규칙/프로세스/경로-비종속-운영-표준.md`(forge) §4.4 · `규칙/프로세스/플러그인-자체-개발표준.md`(forge) §7

## 좋은 예 / 나쁜 예

```markdown
# 나쁜 예 — 클릭 불가 & URL 인코딩 누락
법무관리/tasks/_current.md에서 확인
설계서: [CRM] CRM 데이터 삭제 기능 개선_v1.0.pdf

# 좋은 예 — 클릭 가능 + URL 인코딩
[법무관리/tasks/_current.md](../법무관리/tasks/_current.md)에서 확인
설계서: [`[CRM] CRM 데이터 삭제 기능 개선_v1.0.pdf`](../../문서/01_신규/%5BCRM%5D%20CRM%20데이터%20삭제%20기능%20개선_v1.0.pdf)
```

## 파일별 상대 경로 기준

| 현재 파일 위치 | douzone-forge 루트로 가려면 |
|--------------|---------------------------|
| `CLAUDE.md` (루트) | `./` |
| `프로젝트/*.md` | `../` |
| `Amaranth10/법무관리(LTE)/tasks/*.md` | `../../../` |
| `Amaranth10/법무관리(LTE)/context/GNB/*.md` | `../../../../` |
| **플러그인 자산** (`skills/`·`commands/`·`rules/`) | ⛔ **상대경로 없음** — 백틱 평문 + `(forge)` |

## 관련 자동화 (2026-08-13 현행화)

검출은 **2층**으로 돈다. 두 층은 경쟁이 아니라 보완이다.

| 층 | 무엇 | 시점 | 범위 |
|---|---|---|---|
| ① 쓰기 시점 | `hooks/link-integrity-check.sh` | PostToolUse (Write·Edit) | **방금 쓴 파일 1개** |
| ② 잔존 검출 | `hooks/link-integrity-scan.sh` → `규칙/프로세스/scripts/linkcheck.py`(forge) | SessionStart (세션 1회) | **워크스페이스 전수** · 증가분만 보고 |

- 판정 정본은 `규칙/프로세스/scripts/linkcheck.py`(forge) 하나다. **자체 정규식으로 세지 않는다** — 직전 회차 수치와 비교할 수 없게 되고, 균형 괄호를 오탐한다.
- 수동 실행: `python3 규칙/프로세스/scripts/linkcheck.py active`
- 판정 규격: `_개인/점검/정기종합점검-규격.md`(forge) 항목 11
