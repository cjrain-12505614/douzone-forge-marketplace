# 피드백 검토판 (dz-feedback-review) — 질문 페이지

> **용어 풀이**: 질문 페이지(결정받을 질문을 카드로 담은 HTML 한 장) · 카드(질문 하나 — 요약·왜 묻는가·선택지·추천·결정 칸) · 회차(한 번에 묻고 답받는 묶음, 같은 페이지에 이어 붙는다) · 창구(`fbq.py serve` — 내 맥 안에서만 열리는 작은 웹 서버. 「답변 완료」 답을 받으면 저장하고 끝난다) · 토큰(창구 주소에 붙는 일회용 비밀값, 이 값을 가진 페이지만 답을 보낼 수 있다) · 시안(demo — 선택지마다 실제로 눌러 볼 수 있게 만든 HTML 파일) · 질문 데이터(spec — 카드 내용을 담은 JSON 파일) · playwright(브라우저를 자동으로 움직이는 시험 도구) · iframe(페이지 안에 다른 페이지를 끼워 보이는 틀) · localStorage(브라우저 저장소)

## 0. 이 스킬이 하는 일

결정받을 질문이 생기면 **채팅에 늘어놓지 않고 질문 페이지를 만들어 크롬에 띄우고, 사용자가 「답변 완료」를 누르면 그 답을 바로 받아 처리한다.** 문서를 만드는 도구가 아니다. 질문 → 선택·의견 → 자비스 회신이 중심이다.

HTML 로 묻는 이유는 버튼이 아니라 **채팅으로는 보여 줄 수 없는 것을 보여 주기 위해서**다(2026-10-01 차민수 수석 지시: 「PoC 방안을 선택해야 할 경우 동작되는 2개를 띄워주고 어떤게 나은지를 고를 수도 있는거잖아」). 그래서 카드에는 글 말고도 흐름도·표·전후 비교 같은 그림과, 선택지마다 실제로 동작하는 시안을 나란히 넣을 수 있다.

도구는 `scripts/fbq.py` 하나(파이썬 표준 라이브러리만, 렌더 점검만 playwright 선택)이고, 틀은 `assets/page.html`, 질문 데이터 예시는 `assets/question-spec.example.json`, 카드 글쓰기 규칙과 좋은 예·나쁜 예는 [`references/카드작성가이드.md`](references/카드작성가이드.md) 에 있다.

## 1. 언제 쓰나

| 상황 | 할 일 |
|---|---|
| 결정받을 질문이 **2개 이상** | 이 스킬로 묻는다(사용자가 부르지 않아도) |
| 질문은 하나라도 **선택지마다 결과를 비교**해야 함 | 이 스킬로 묻는다 |
| PoC·화면안·동작 방식처럼 **직접 보고 써 봐야** 고를 수 있음 | 이 스킬로 묻고, 선택지마다 시안을 만들어 나란히 띄운다 |
| 사용자가 「질문 페이지로」·「피드백 받을 HTML」·「자세한 피드백」 등으로 요청 | 이 스킬로 묻는다 |
| 예·아니오 수준 확인 **하나** | 채팅으로 묻는다(페이지를 만들지 않는다) |

결정받을 질문을 채팅 글로 여러 개 나열하려는 순간이 이 스킬을 쓸 때다. 2026-10-01 에 카드 길이 기준 세 가지 안을 채팅 글로 물었는데, 사용자가 원한 것은 바로 그런 질문을 페이지로 받아 답하는 환경이었다(차민수 수석: 「자비스가 질문하면 내가 피드백하는 환경을 원했어」).

## 2. 준비 — 경로 변수와 폴더

**Bash 도구는 명령 사이에 변수가 이어지지 않는다.** 아래 명령을 낼 때마다 이 줄들을 맨 앞에 붙인다(값은 절대 경로로).

```bash
FBQ="<스킬 폴더>/scripts/fbq.py"      # 스킬을 불러올 때 맨 위에 나오는 스킬 폴더(Base directory) 뒤에 /scripts/fbq.py
Q="/절대경로/douzone-forge/_개인/sessions/{작업}/질문"   # 지금 작업의 세션 폴더 아래 질문/
T="search-poc"                          # 주제 키 — 영문·숫자·하이픈만(한글 금지, §10)
P="$Q/20261001-$T.html"                 # 질문 페이지 = 질문/{YYYYMMDD-주제}.html
N=1                                     # 지금 회차
```

스킬 폴더 경로가 보이지 않으면 설치 캐시에서 찾는다(zsh 는 맞는 파일이 없는 `*` 글롭에서 오류를 내므로 `ls` 대신 `find` 를 쓴다).

```bash
find ~/.claude/plugins/cache -path '*/douzone-forge/*/skills/dz-feedback-review/scripts/fbq.py' 2>/dev/null | sort -V | tail -1
```

질문 페이지와 답은 **지금 작업의 세션 폴더**에 둔다. 다운로드 폴더와 스크래치패드(세션이 끝나면 지워지는 임시 폴더)에는 두지 않는다.

```
_개인/sessions/{작업}/질문/
  20261001-search-poc.html             질문 페이지(회차가 이어 붙는 한 파일)
  20261001-search-poc.bak-r1.html      append 가 남긴 직전 판(회차마다 하나)
  demo/search-poc-a.html               시안(동작하는 HTML) — 페이지 폴더 기준 상대 경로로 부른다
  spec/search-poc-r1.json              질문 데이터(회차마다 하나)
  답/search-poc-r1.json                창구가 받은 답(「답변 완료」)
  답/search-poc-r1.txt                 대화창에 붙여 넣어 받은 답 원문
  답/search-poc-r1-reflected.json      반영한 곳 기록(다음 회차 표에 들어간다)
  답/.serve-search-poc-r1.log          창구 기록 — 첫 줄이 접속 주소(포트 다시 쓸 때 필요, §9). 주제 키가 들어 있어 한 폴더의 다른 페이지 로그와 겹치지 않는다
```

## 3. 순서

### ① 질문 데이터 작성

먼저 폴더를 만든다.

```bash
mkdir -p "$Q/spec" "$Q/demo" "$Q/답"
```

카드 내용을 JSON 으로 쓴다(형식 §4, 글쓰기 §5, 보여 주기 §6). 시안이 필요한 질문이면 시안 HTML 을 먼저 `$Q/demo/` 에 만든다 — 없으면 카드에 「시안 파일을 찾을 수 없습니다: 경로」가 나온다. Write 도구로 `$Q/spec/$T-r1.json` 에 저장한다.

### ② 페이지 만들기

```bash
python3 -B "$FBQ" new --spec "$Q/spec/$T-r1.json" --out "$P"
```

질문 데이터에 빈 칸(선택지 설명·「고르면」, 추천인데 대가 없음 등)이 있으면 고칠 곳을 줄마다 알려 주고 페이지를 만들지 않는다(종료 1). 성공하면 `1회차 질문 3건 · 시안 2개 · 저장 키 dzfb:20261001-search-poc-r1` 처럼 찍힌다. 같은 이름의 페이지가 이미 있으면 거부한다 — 이어지는 질문은 ⑦의 `append` 를 쓴다.

### ③ 점검

```bash
python3 -B "$FBQ" check "$P" --render
```

정적 점검(카드 필수 칸·카드 번호 중복·카드 안 접는 요소·외부 자원·세리프 글꼴·이모지·금지 어휘·스크립트 문법)에 더해, `--render` 는 크롬으로 실제로 그려 세리프 글자 수·대비 4.5 미달·1280/375 폭 가로 넘침·콘솔 오류를 잰다. 시안 파일도 함께 본다 — 외부 자원·세리프·이모지에 더해 다른 파일·주소 부르기(한 파일 규칙)와 고딕 글꼴 선언, `--render` 에서는 시안 글자가 고딕으로 그려지는지까지.

| 종료 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 통과(`렌더: 세리프 0 · 대비 미달 0 · 넘침 1280=0 375=0 · 콘솔 오류 0`) | ④로 |
| 1 | 문제 있음(`[문제]` 줄) | 질문 데이터·시안을 고치고 1회차면 `new … --force` 로 다시 만든다. append 뒤라면 §9 「회차를 되돌릴 때」 |
| 3 | playwright 가 없어 렌더 점검을 못 함 | 정적 점검만 통과한 것이다. 「렌더 점검 못 함」을 사용자 보고에 적는다 |

화면을 눈으로 보려면 `--shots "$Q/../shots"` 를 붙이면 `w1280.png`·`w375.png` 가 생긴다. 전체 페이지 캡처에서는 시안 칸이 빈 흰 칸으로 찍히므로(시안은 실제로는 떠 있다), 시안마다 `demo-{카드번호}-{선택지번호}-w1280.png`·`-w375.png` 를 따로 찍는다 — 시안이 제대로 그려졌는지는 이 그림으로 본다. `--render` 는 설치된 Google Chrome 이 있으면 그것으로, 없으면 playwright 의 Chromium 으로 그린다(출력의 `렌더(chrome)`·`렌더(chromium)`).

### ④ 창구 띄우기 + 크롬에 열기

창구는 **Bash 도구의 `run_in_background: true` 로** 띄운다. 기다리는 동안 자비스는 턴을 끝내고, 창구가 끝나면(답 도착 또는 시간 초과) 종료 알림으로 다시 깨어난다.

```bash
# ④-1 창구 — run_in_background: true 로 실행
mkdir -p "$Q/답"; set -o pipefail; python3 -B "$FBQ" serve --page "$P" --out "$Q/답/$T-r$N.json" 2>&1 | tee "$Q/답/.serve-$T-r$N.log"
```

```bash
# ④-2 다음 호출에서 — 접속 주소(로그의 첫 http:// 줄)를 읽어 크롬에 연다
URL="$(grep -m1 '^http://' "$Q/답/.serve-$T-r$N.log")"; echo "$URL"
python3 -B "$FBQ" open --url "$URL" --match "$(basename "$P")"
```

- `URL` 이 비어 있으면 창구가 아직 주소를 쓰기 전이거나 뜨지 못했다. 로그에 `오류:` 줄이 있으면 그 내용대로 고치고, 없으면 ④-2 를 한 번 더 낸다.
- 창구는 접속 주소를 늘 첫 줄에 찍는다(지난 답 파일을 옮겼다는 안내 등은 그다음 줄). 그래도 주소는 `grep -m1 '^http://'` 로 읽는다 — 로그에 다른 줄이 섞여도 주소만 집는다.
- 주소 모양: `http://127.0.0.1:53829/20261001-search-poc.html?t=토큰`. 창구는 빈 포트를 잡고, 기본 6시간 뒤 스스로 끝난다(`--timeout 초`).
- `open` 은 크롬에 같은 파일명의 탭이 있으면 **그 탭 주소만 바꾸고**(새 탭을 만들지 않는다), 없으면 새로 연다. 「새 창으로 크게 보기」 탭(주소 끝 `#full=…`)은 파일명이 같아도 질문 탭이 따로 있으면 건너뛴다. 크롬 자동화 권한이 없거나, 처음 쓰는 맥에서 「크롬 제어 허용」 창이 떠 30초 안에 탭을 읽지 못하면 경고를 찍고 새로 연다.
- `open` 이 종료 0 이 아니면 ⑤ 안내를 하기 전에 출력의 `오류:` 줄로 원인을 확인한다(크롬에 페이지가 뜨지 않은 것이다).
- `tee` 와 `set -o pipefail` 은 접속 주소를 파일로 남기면서(§9 포트 다시 쓰기에 필요) 창구의 종료 코드를 그대로 돌려받기 위한 것이다.

### ⑤ 사용자에게 한 줄 안내하고 턴을 끝낸다

질문 내용을 채팅에 다시 늘어놓지 않는다. 예:

> 크롬에 질문 페이지를 띄웠습니다(질문 3건 — 첫 질문은 시안 두 개를 직접 눌러 보고 고르시면 됩니다). 다 고르신 뒤 「답변 완료」를 눌러 주세요. 연결이 끊겼다고 나오면 「결과 복사」 후 여기에 붙여 넣어 주셔도 됩니다.

### ⑥ 답 받기

**가) 종료 알림으로 받음** — 창구가 끝나면 알림에 종료 코드가 온다.

| 종료 코드 | 마지막 줄 | 뜻 |
|---|---|---|
| 0 | `ANSWER_RECEIVED {답 파일}` | 답을 받아 저장함 |
| 2 | `TIMEOUT` | 시간 안에 답이 오지 않음 — §9. 마지막 줄이 `TIMEOUT` 일 때만 시간 초과다 |
| 2 | `fbq.py serve: error: …` | 명령 인자 오류(예: `--port` 에 숫자가 아닌 값, `--timeout 1h`) — 창구가 뜨지 않았다. 명령을 고쳐 다시 띄운다(§9 에서 로그에 `http://` 줄이 없으면 `--port` 없이 띄운다) |
| 130 · 143 등 | (없음) | 창구가 중간에 꺼짐(중단·세션 종료) — §9 |

창구는 시작할 때 `--out` 경로에 지난 답 파일이 있으면 지우지 않고 `{이름}.old-{시각}.json` 으로 옮긴다(접속 주소 다음 줄에 stderr 로 한 줄). 시간 초과 직후에 들어온 답도 저장했으면 종료 0 이다. 그래서 창구가 끝난 뒤 `--out` 에 답 파일이 있으면 언제나 이번 실행에서 받은 답이고, 종료 0 과 답 파일 유무가 늘 맞는다(2026-10-01 실측).

```bash
python3 -B "$FBQ" read --answer "$Q/답/$T-r$N.json"
```

**나) 사용자가 결과 문장을 대화창에 붙여 넣음** — 붙여 넣은 글을 원문 그대로 파일에 남기고 읽는다(앞뒤 인사말·`>` 인용·빈 줄이 섞여도 읽는다). 이때는 아직 떠 있는 창구를 멈춘다 — TaskStop 도구로 그 백그라운드 작업을 끄고, 작업 번호를 모르면 `ps -ax -o pid,command | grep '[f]bq.py serve'` 로 프로세스 번호를 찾아 `kill 번호`.

```bash
cat > "$Q/답/$T-r$N.txt" <<'EOF'
(사용자가 붙여 넣은 글 그대로)
EOF
python3 -B "$FBQ" read --text "$Q/답/$T-r$N.txt" --page "$P"
```

`--page "$P"` 를 주면 그 페이지의 이번 회차 카드 번호로 읽는다 — 직접 정한 번호(`PoC-1` 등)도 정확히 읽고, 글에서 빠진 카드를 알려 준다. 붙여 넣은 글은 늘 `--page` 를 붙여 읽는다.

`read` 는 JSON 을 표준 출력으로 낸다. 카드마다 `id`·`title`·`choice`(`"1"`·`"2"`… 고른 선택지 번호 / `"modify"` 수정 / `"hold"` 보류 / `"none"` 미결정)·`choiceLabel`(`① 채택(추천)`·`② 선택`…)·`adopted`(추천을 골랐는지)·`memo`(메모 원문, 줄바꿈 포함)가 들어 있고, `counts` 에 전체·결정·미결정 수, `warnings` 에 읽으며 의심스러웠던 점, `loss_risk` 에 그 가운데 **답·메모가 빠졌거나 잘못 붙었을 수 있는 것**(카드 줄이 모자람·읽지 못한 카드 줄·카드 줄 사이의 읽지 않은 줄·들여쓰기 없이 메모로 이은 줄)이 있다. `warnings` 가 있으면 그 줄을 원문과 대조한다 — 예: 붙여 넣은 글 끝의 「감사합니다」가 마지막 메모 바로 다음 줄(빈 줄 없음)에 붙어 있으면 메모의 일부로 읽히고 `메모 다음 줄이 들여쓰기 없이 붙어 있어 메모로 이었습니다` 경고가 나온다(2026-10-01 실측). 그때는 답 원문 파일(`$Q/답/$T-r$N.txt`)에서 그 줄 앞에 빈 줄을 넣거나 지우고 다시 읽는다 — `loss_risk` 가 남아 있으면 ⑦의 `append` 가 거부한다. 답을 하나도 못 읽으면 종료 1.

### ⑦ 반영 → 다음 회차 또는 끝

1. 답을 §7 규칙대로 반영한다. 메모는 원문 그대로 읽는다.
2. 카드마다 무엇을 어디에 반영했는지 적는다(다음 회차 「이전 회차 — 반영됨」 표의 「반영한 곳」 칸이 된다). 비워 두면 「–」로 남는다.

```bash
cat > "$Q/답/$T-r$N-reflected.json" <<'EOF'
{"R1-1": "화면 설계 — 한 줄 목록으로 확정", "R1-2": "개발 계획 2단계 — 시안 확인 반나절로(2회차 R2-1에서 다시 확인)", "R1-3": "2회차 R2-2로 다시 물음"}
EOF
```

3. **이어서 물을 것이 있으면** 다음 회차 질문 데이터(`$Q/spec/$T-r2.json`)를 쓰고 붙인다. 이번 회차 카드는 「N회차 — 반영됨」 표(번호·질문·고르신 답·메모 원문·반영한 곳)로 접혀 이전 회차 묶음 맨 위에 들어가고, 새 카드가 붙고, 저장 키가 `…-r2` 로 바뀐다. 원본은 `{이름}.bak-r1.html` 로 남는다.

```bash
A="$Q/답/$T-r$N.json"; [ -f "$A" ] || A="$Q/답/$T-r$N.txt"     # 창구로 받았으면 .json, 붙여 넣기로 받았으면 .txt
python3 -B "$FBQ" append --page "$P" --spec "$Q/spec/$T-r$((N+1)).json" --answers "$A" --reflected "$Q/답/$T-r$N-reflected.json"
```

   `--answers` 에는 창구가 받은 JSON, 붙여 넣기 원문 파일(`.txt`), `read` 출력 무엇이든 줄 수 있다. 붙여 넣은 글을 읽은 `read` 출력은 그 읽기의 `loss_risk`·머리 질문 수를 이어받아 원문 파일과 같은 기준으로 검사한다. 다음 경우에는 페이지를 바꾸지 않고 종료 1 — 답의 회차·저장 키가 페이지와 다름(다른 회차·다른 페이지의 답) · 붙여 넣은 글에서 읽은 카드 수가 이번 회차 카드 수나 글 머리의 질문 수와 다름 · `loss_risk` 경고가 있음(사용자 결정이 「미결정」·잘린 메모로 잘못 남지 않게). 이때는 붙여 넣기 원문(`$Q/답/$T-r$N.txt`)을 사용자 글과 대조해 고친 뒤 그 원문으로 다시 붙인다(`read` 출력 JSON 을 손으로 고치지 않는다). `--force` 는 이 거부와 점검 실패를 **모두** 무시하므로, 읽은 내용이 맞다고 확인했을 때만 쓴다. 그다음 `N=2` 로 ③ 점검 → ④ 창구(새 토큰) → ⑤ → ⑥ 을 다시 돈다. 열린 탭은 `open` 이 그 자리에서 새 주소로 바꾼다.

4. **더 물을 것이 없으면** 끝이다. 마지막 회차를 어디에 어떻게 반영했는지는 채팅으로 보고한다(페이지에 접어 넣지 않는다). 확정된 결정을 오래 보관해야 하면 dz-decision-tracker 에 등재한다.

## 4. 질문 데이터 형식

예시 전문: `assets/question-spec.example.json`(시안 2개를 나란히 둔 질문 · 단계 흐름 그림 질문 · 추천 없는 질문 + 선택지 그림). 밑줄(`_`)로 시작하는 키는 설명용이라 무시한다.

```json
{
  "title": "검색 결과 화면 PoC 고르기",
  "fbKey": "20261001-search-poc",
  "kicker": "검색 개선 · 화면 결정 · 1회차",
  "lead": ["이번 회차에는 결과 화면 모양과 고치는 순서를 정합니다.", "첫 질문은 두 시안을 직접 눌러 보고 고르시면 됩니다."],
  "questions": [
    {
      "title": "검색 결과를 보여 줄 화면 모양",
      "summary": "검색 결과를 <b>한 줄 목록</b>으로 보여 줄지, <b>카드 묶음</b>으로 보여 줄지 고릅니다.",
      "why": ["결과 화면 모양은 한 번 정하면 필터·정렬·엑셀 내려받기가 모두 그 모양에 맞춰 만들어집니다."],
      "visual": "<div class=\"tbl-wrap\"><table class=\"v-table\">…</table></div>",
      "options": [
        {"name": "한 줄 목록 — 결과 한 건을 한 줄로", "desc": "제목·날짜·담당자를 한 줄에 놓습니다.",
         "then": "한 화면에 결과가 많이 보입니다. 요약은 줄마다 한 번씩 눌러야 봅니다.",

```

| 키 | 필수 | 내용 · 쓸 수 있는 것 |
|---|---|---|
| `title` | 1회차 필수 | 페이지 제목(글자). 회차가 바뀌어도 그대로 — append 는 이 값을 쓰지 않는다 |
| `fbKey` | 권장 | 저장 키 앞부분 `YYYYMMDD-영문주제`. `-r1` 은 도구가 붙인다. 없으면 파일 이름에서 만든다 |
| `kicker` | 선택 | 분류 한 줄(글자). append 때 비우면 앞 회차 문구의 「N회차」 숫자만 바꿔 쓴다 |
| `h1` | 선택 | 머리 제목(글자, 없으면 `title`). 뒤의 「— 질문 N건」은 틀이 붙인다 |
| `lead` | 필수 | 리드 — 결론 먼저: 무엇을 정하는 회차인지, 직전 회차에서 무엇을 반영했는지. HTML 또는 문단 목록 |
| `questions[].id` | 선택 | 생략하면 `R{회차}-{순번}`(권장). 직접 정하면 영문·숫자·`-_.` 만(예 `PoC-1`·`Q3`, 그 밖의 글자는 `new`·`append` 가 거부). 이전 회차 번호와 겹치면 거부. 직접 정한 번호의 붙여 넣은 답은 `read --page` 로 읽는다(`append` 는 페이지 번호로 저절로 읽는다) |
| `questions[].title` | 필수 | 카드 제목(글자) |
| `summary` | 필수 | 한 줄 요약 — 무엇을 고르는가. 인라인 HTML(`<b>`·`<code>`·`<a>`)만 |
| `why` | 필수 | 왜 묻는가 — 배경·걸려 있는 것. HTML 또는 문단 목록(목록·여러 문단 가능) |
| `visual` · `visual_label` | 선택 | 카드 보기 칸(그림·표, §6)과 그 이름표(기본 「한눈에」) |
| `options[].name` · `desc` · `then` | 셋 다 필수 | 선택지 이름(내용으로) · 설명 · 「고르면」 무엇이 달라지는지. 인라인 HTML 만 — 그림·표는 `visual` 에 |
| `options[].visual` | 선택 | 선택지 보기 칸 |
| `options[].demo` · `demo_height` | 선택 | 시안 파일(페이지 폴더 기준 상대 경로) · 높이 px(120~3000, 기본 420) |
| `rec` | 선택 | 추천 선택지 번호(1부터). `0` 또는 생략 = 추천 없음 |
| `rec_text` · `cost` | `rec` 가 1 이상이면 필수 | 추천 이유 · 대가(그 추천으로 잃는 것). 인라인 HTML 만 |

결정 버튼은 도구가 만든다 — 추천 선택지는 「① 채택(추천)」으로 맨 앞, 나머지는 「② 선택」…, 그리고 「수정」·「보류」. 다시 누르면 해제되고, 메모 칸이 카드마다 하나 있다.

## 5. 카드 작성 규칙 (요약 — 상세와 실례는 [카드작성가이드](references/카드작성가이드.md))

1. **모두 펼친다.** 카드 안에 접는 요소(`<details>`·「자세히」)를 넣지 않는다. 길어도 된다(1회차 Q3 답: 「접는것 없이 모두 펼쳐서 길더라도 이해하고 넘어가길 원한다」). `check` 가 카드 안 `<details>` 를 문제로 잡는다.
2. **선택지는 내용으로 쓴다.** 「v7 반영안 수준」·「1단계 견본 수준」·「B안」·파일명처럼 자비스가 붙인 이름·약칭으로 대신하지 않는다. 사용자가 그 이름을 지은 적이 없으면 무엇을 가리키는지 알 수 없다.
3. **「고르면」은 무엇이 달라지는지 구체적으로** — 화면·일정·비용·되돌릴 수 있는지. 장단점 나열이 아니라 결과.
4. **추천은 하나, 이유와 대가를 함께.** 정말 판단 재료가 부족할 때만 `rec: 0`.
5. **결론 먼저.** 리드는 「이번 회차에 정할 것」부터, 왜 묻는가는 「무엇이 걸려 있는지」부터.
6. **쉬운 말.** 처음 나오는 용어·약어는 그 자리에서 괄호로 푼다. 답변 톤 표준의 금지 어휘 다섯 낱말은 `check` 가 잡는다.
7. **지어낸 사실 금지.** 수치·일정·사람·출처는 확인한 것만. 모르면 「확인 필요」라고 쓴다.
8. **다듬기로 늘리지 않는다.** 같은 뜻을 다르게 쓰는 문장 다듬기는 하지 않는다. 늘어나는 문장은 판단 재료여야 한다(1단계 견본이 다듬기 지적 누적으로 3.2배로 불어난 실례 — 가이드 §4).

## 6. 보여 주기 규칙

**설명 한 문단보다 그림 하나가 빠를 때 그림을 쓰고, 써 봐야 고를 수 있는 것은 동작하는 시안을 나란히 띄운다.** 장식용 그림은 넣지 않는다.

| 무엇을 보여 주나 | 넣는 곳 | 모양 |
|---|---|---|
| 단계·순서·흐름 | 카드 `visual` | `<ol class="v-flow"><li><span class="v-k">1단계</span><b>제목</b><span class="v-d">설명</span></li>…</ol>` — `li.is-key` 강조. 375 폭에서 세로로 바뀐다 |
| 두세 가지를 나란히 | 카드 또는 선택지 `visual` | `<div class="v-cols"><div class="v-col">…</div><div class="v-col is-key">…</div></div>` — 2~3열, 375 폭에서 위아래 |
| 항목별 비교 | 카드 `visual` | `<div class="tbl-wrap"><table class="v-table"><thead>…</thead><tbody>…</tbody></table></div>` |
| 수치 크기 | 카드 `visual` | `<div class="v-bars"><div class="v-bar"><span class="v-bar-k">항목</span><span class="v-bar-t"><span class="v-bar-f" style="width:62%"></span></span><span class="v-bar-v">62%</span></div></div>` |
| 그 밖의 그림 | 어디든 | 인라인 SVG/HTML. SVG 색은 `style="fill:var(--blue)"` 처럼 style 속성으로 준다. 보조색은 `--cyan`(장식 전용 — 글자 금지). 그림 설명은 `<p class="v-cap">` |
| 선택지를 고르면 어떻게 되는지 | 선택지 `visual` | 위 모양 또는 화면 모습 |
| 화면안·PoC·동작 방식 | 선택지 `demo` | 동작하는 시안 HTML |

시안(demo) 규칙:

- `질문/demo/` 아래에 둔다. 한 질문 폴더에 페이지가 여럿이면 시안 이름 앞에 주제 키를 붙인다(`demo/search-poc-a.html`). 경로에 공백·탭을 쓰지 않는다(`new`·`check` 가 거부한다 — 공백은 `-` 나 `_` 로).
- **선택지가 둘 이상이고 모두 시안이 있으면** 카드에 「직접 써 보기」 칸이 생겨 시안이 나란히 놓인다(1280 폭에서 시안 2개면 2열·3개 이상이면 3열, 375 폭에서는 위아래). 써 보기 좋은 것은 2개까지다. 일부 선택지에만 있으면 그 선택지 안에 들어간다. 시안마다 「새 창으로 크게 보기」 링크가 붙는다.
- 시안은 iframe `sandbox="allow-scripts allow-forms allow-modals allow-popups"` 로 뜬다(같은 출처 권한 없음 — 시안이 질문 페이지의 저장값에 손대지 못한다). 「새 창으로 크게 보기」도 시안 파일을 직접 열지 않고 질문 페이지를 `#full=시안경로&c=카드번호&n=선택지번호` 로 열어 sandbox iframe 하나만 화면 가득 그리므로(머리 띠·탭 제목에 「R1-1 카드 제목 — ② 선택지 이름」이 나와 어느 창이 어느 선택지인지 구분된다), 새 창의 시안도 저장값에 닿지 못한다(파일로 열 때·창구로 열 때 모두, 2026-10-01 실측). 창구는 페이지 말고 내주는 파일(시안·그림)에 `Content-Security-Policy: sandbox …` 머리를 붙여, 시안 주소를 직접 열어도 출처가 없다. 다만 **시안 파일을 브라우저에서 직접 파일로 열면 sandbox 밖**이다 — 그래서 시안은 `localStorage`·쿠키를 아예 쓰지 않는다(sandbox 안에서는 접근하면 오류). 상태는 변수로 들고 있는다(`check` 경고).
- **시안은 HTML 한 파일이다.** CSS·JS 는 파일 안에 넣고, 그림은 인라인 SVG 나 `data:` 주소, 예시 자료는 스크립트 안 변수로 둔다. sandbox(출처 없음) 때문에 파일로 열면 같은 폴더의 `<script src>`·`<link href>`·`<img src>` 까지 모두 막히고, 창구로 열어도 `fetch`·`XMLHttpRequest`·`<script type="module">` 은 CORS(다른 출처 요청 차단)로 막힌다. `check` 가 시안의 다른 파일·주소 부르기를 `[문제]` 로 잡는다.
- **시안 `body` 에 고딕 글꼴 목록을 적는다.** 안 적으면 맥 크롬 기본 글꼴인 명조·Times 로 그려진다(2026-10-01 실측). `check` 가 선언이 없는 시안을, `check --render` 가 고딕 없이 그려진 시안 글자를 `[문제]` 로 잡는다.
- 시안도 질문 페이지와 같은 기준을 따른다: 외부 자원(CDN(외부 배포 서버)·웹 글꼴) 금지, 세리프 글꼴 금지, 이모지 금지. `check` 가 시안 파일까지 본다.
- 페이지 쪽에 `<script>` 를 따로 넣지 않는다(`check` 경고) — 움직이는 것은 시안으로 옮긴다.
- 시안 파일이 없으면 그 자리에 「시안 파일을 찾을 수 없습니다: 경로」가 나온다. 만든 뒤 페이지를 다시 만든다(1회차면 `new --force`).
- **비교할 PoC 가 이미 있고 한 파일로 묶이지 않으면**(개발 서버로 돌거나 여러 파일), `demo` 에 그 주소·폴더를 넣지 않는다(`new` 가 주소를 거부한다). 비교할 화면만 한 파일 시안으로 만들고, 실제 PoC 와 다른 점을 선택지 `desc` 에 적는다(확인한 것만). 실행 주소는 `desc` 에 `<a href="http://localhost:포트/" target="_blank">` 로 둔다 — 이 링크는 그 개발 서버가 이 맥에서 돌고 있을 때만 열린다.

## 7. 답 처리 규칙

- 「답변 완료」로 받은 답은 **사용자의 명시적 답**으로 처리한다. 사용자가 이 경로를 직접 요청했다(2회차 R2-1 메모: 「답하는 동안 모니터링해서 답변완료(버튼)을 클릭하면 처리하는 편리성」).
- 승인을 묻는 카드에서는 **고른 선택지에 적힌 대로만 진행한다.** 진행을 뜻하는 선택지(추천이든 아니든)를 골랐을 때만 그 카드에 적힌 단계의 진행 승인이고, 「고칠 점이 있음」 같은 다른 선택지는 승인이 아니다(2회차 R2-1 에서 「② 고칠 점이 있음」을 고른 사례). 다음 단계까지 넘겨짚지 않는다.
- **배포·삭제·외부 발신처럼 되돌리기 어려운 행동은 그 카드에 그 행동을 명시해 물은 경우에만** 진행한다. 메모에 카드 범위 밖의 새 지시가 있으면 바로 실행하지 않고 다음 회차 카드나 채팅으로 확인한다.
- 「수정」은 메모 내용대로 고친 안을 다시 확인받는다(다음 회차 카드 또는 채팅). 「보류」·「미결정」은 진행하지 않는다 — 다음 회차에 다시 물을 것이면 다음 질문 데이터에 **새 번호로 다시 넣는다**(append 는 미결정 카드를 다음 회차로 옮겨 주지 않는다).
- 메모는 고치거나 요약하지 않고 원문 그대로 읽고, 「반영됨」 표에도 원문 그대로 들어간다. 사용자 메모의 금지 어휘·이모지도 고치지 않는다 — `check` 는 반영됨 표의 메모 칸을 점검하지 않는다.
- 추천과 다른 답이 오면 그대로 따른다. 이유를 되묻지 않는다(근거가 약해 보이면 반영 전에 그 점만 짚는다).

## 8. 보안

- 창구는 `127.0.0.1` 에만 열린다(같은 맥 밖에서는 접속 불가).
- 답 전송(`POST /answer`)과 연결 확인(`GET /ping`)은 일회용 토큰이 맞아야 받는다(틀리면 403). 주소의 `Host` 가 `127.0.0.1:포트`·`localhost:포트` 가 아니면 거부한다 — 다른 사이트가 이름을 127.0.0.1 로 돌려 들어오는 것을 막는다.
- 답을 한 번 받으면 저장하고 끝난다(그 뒤 전송은 받지 않는다). 시간 초과로도 끝난다. 시작할 때 같은 경로의 지난 답 파일은 `.old-{시각}.json` 으로 옮기므로, 지난 답(사용자가 바꾸겠다고 한 답일 수 있다)을 이번 답으로 읽는 일이 없다.
- 페이지 폴더 안 파일(시안·그림)만 내준다. `..`·`%2e%2e` 같은 인코딩 우회·심볼릭 링크로 폴더 밖에 나가는 요청, 점(`.`)으로 시작하는 숨김 파일은 403 이다(2026-10-01 실측).
- 단, **폴더 안 파일은 토큰 없이 내준다**(시안이 토큰 없이 불려야 해서). 질문 폴더에 비밀정보(자격증명·개인정보 원본)를 두지 않는다. 페이지 말고 내주는 파일에는 `Content-Security-Policy: sandbox allow-scripts allow-forms allow-modals allow-popups` 머리를 붙인다(시안 주소를 직접 열어도 질문 페이지 저장값에 닿지 못하게).
- 답 저장이 끝난 뒤 응답을 보내다 연결이 끊겨도(응답 전 RST) 창구는 받은 것으로 보고 종료 0 으로 끝난다. 메모에 짝 없는 대리 문자(이모지 반쪽 등)가 섞이면 `�`(U+FFFD)로 바꿔 저장한다.

## 9. 연결 없음 · 창구가 사라졌을 때

| 상황 | 페이지에 보이는 것 | 대처 |
|---|---|---|
| 페이지를 파일(`file://`)로 열었음 | 칩 「자비스 연결 없음 — 결과 복사로 보내 주세요」 | 사용자가 「결과 복사」 후 붙여 넣는다 → ⑥-나). 창구로 받고 싶으면 ④를 한다 — 단, 사용자가 이미 고르기 시작했다면 ④로 바꾸지 말고 「결과 복사」로 받는다(④를 하면 탭 주소가 `http://127.0.0.1:포트` 로 바뀌어, 파일로 열었을 때 입력한 답이 새 주소에서 보이지 않는다 — 브라우저 저장소는 주소의 출처마다 따로다) |
| 답하는 중에 창구가 끝남(세션 종료·시간 초과) | 탭은 그대로 있고 입력도 남지만, 「답변 완료」를 누르면 「자비스가 대기 중이 아닙니다. 「결과 복사」 후 대화창에 붙여 넣어 주세요」, 칩은 「연결 없음」. **새로 고침하면 페이지가 뜨지 않는다**(창구가 페이지를 내주던 것이라서) | 아래 「같은 포트로 다시 띄우기」 |
| 새 세션에서 이어받음 | — | `ls -t "$Q" "$Q/답"` 로 페이지(`.bak-r` 이 없는 `.html`)와 마지막 답 파일을 찾는다. `python3 -B "$FBQ" check "$P" --json` 출력의 `info.round` 가 지금 회차다. 지금 회차 답 파일(`답/$T-r$N.json` 또는 `.txt`)이 이미 있으면 ⑦부터, 없으면 같은 포트로 다시 띄운다 |
| 답을 받은 뒤(append 전) 사용자가 같은 회차 답을 바꾸겠다고 함 | 탭에는 고른 답·메모가 그대로 있고 「답변 완료」는 「보냈습니다」로 잠겨 있다(새로 고치면 풀린다) | ④를 새로 하지 말고 아래 「같은 포트로 다시 띄우기」(포트는 지난 로그의 `http://` 줄에서 읽는다). 빈 포트로 띄우면 탭 출처가 바뀌어 고른 답·메모가 보이지 않는다. 지난 답 파일은 창구가 `.old-{시각}.json` 으로 옮겨 두고, 새 답이 `답/$T-r$N.json` 에 들어온다 |

**같은 포트로 다시 띄우기.** 입력 중인 답은 브라우저 저장소에 「주소의 포트」별로 따로 들어간다. 같은 포트로 띄우면 입력이 그대로 남고, 다른 포트로 띄우면 빈 카드로 보인다(2026-10-01 실측: 같은 포트 — 고른 답·메모 유지 / 다른 포트 — 사라짐). 그래서 같은 회차를 다시 띄울 때는 지난 로그의 접속 주소(`http://` 줄)에 있는 포트를 그대로 쓴다.

```bash
# run_in_background: true 로 실행 — PORT 는 tee 가 로그를 비우기 전에 읽힌다.
# 로그에 http:// 주소 줄이 없으면(지난번에 창구가 뜨지 못함) PORT 가 비고, --port 없이(빈 포트로) 띄운다
PORT="$(grep -m1 '^http://' "$Q/답/.serve-$T-r$N.log" | sed -nE 's#^http://127\.0\.0\.1:([0-9]+)/.*#\1#p')"; set -o pipefail; python3 -B "$FBQ" serve --page "$P" --out "$Q/답/$T-r$N.json" ${PORT:+--port=$PORT} 2>&1 | tee "$Q/답/.serve-$T-r$N.log"
```

그다음 ④-2 로 `open`(같은 탭 주소만 새 토큰으로 바뀐다). 그 포트를 다른 프로그램이 쓰고 있어 「창구를 열지 못했습니다」가 나오면(종료 1), 이번 회차는 창구를 다시 띄우지도 `open` 하지도 않는다 — `open` 하면 지금 탭이 새 포트 주소로 바뀌어, 입력한 답이 보이지 않게 된다. 사용자에게 지금 탭에서 「결과 복사」 후 대화창에 붙여 넣어 달라고 안내하고 ⑥-나)로 받는다. 다음 회차(append 뒤)는 저장 키가 바뀌므로 ④를 새로 한다(포트를 맞출 필요 없음).

**회차를 되돌릴 때.** append 뒤 점검에 걸리거나 잘못 붙였으면, 직전 판으로 되돌리고 질문 데이터를 고쳐 다시 붙인다.

```bash
cp "${P%.html}.bak-r1.html" "$P"      # r1 = 되돌아갈 회차(백업 이름은 페이지 이름 + .bak-rN.html)
```

## 10. 함정

- **한글 파일명 금지 — 파일 찾기는 영문 키로.** 맥은 한글 파일명을 자모 분리(NFD) 형태로 저장할 때가 있어, 한글 검색어(NFC)로 `grep`·`find` 하면 0건이 나온다(2026-10-01 실측 — 「결정결과」로 찾은 답 파일 0건). 페이지·시안·답 파일 이름은 `20261001-search-poc` 처럼 영문 주제 키로 짓는다. 세션 폴더 이름이 한글인 것은 경로를 통째로 쓰면 문제없다.
- **스크래치패드는 세션이 끝나면 사라진다.** 질문 페이지·시안·질문 데이터·답은 세션 폴더 `질문/` 에 둔다. 다음 회차 append 와 새 세션 이어받기가 이 파일들에 기댄다.
- **다운로드 폴더를 쓰지 않는다.** 사용자마다 위치가 다르고 저장 후 알려 주는 단계가 번거롭다(2회차 R2-1·R2-3 답).
- **셸 변수는 명령 사이에 이어지지 않는다** — §2 의 줄을 매번 붙인다.
- **창구는 주 대화 세션에서 띄운다.** 서브에이전트(워크플로 안 에이전트)가 띄운 백그라운드 명령은 그 에이전트가 최종 응답을 낼 때 함께 끝나 종료 알림도 오지 않는다.
- **`new` 를 같은 페이지에 다시 하면 이전 회차가 사라진다.** 이어지는 질문은 반드시 `append`. `--force` 는 1회차를 고쳐 만들 때만.
- **페이지 HTML 을 손으로 고치지 않는다.** 영역 표지(`<!--fbq:cards-->` 등)·저장 키(`data-fb-key`)가 어긋나면 append 가 거부한다. 고칠 것은 질문 데이터에서 고쳐 다시 만든다.
- **미결정·보류 카드는 다음 회차로 저절로 넘어가지 않는다** — 다음 질문 데이터에 다시 넣는다.
- **이모지·세리프 글꼴·외부 자원**은 페이지와 시안 모두 `check` 에서 문제로 걸린다.

## 11. 다른 스킬과의 경계

| 스킬 | 하는 일 | 이 스킬과의 관계 |
|---|---|---|
| dz-progress-dashboard | 다단계 작업의 진행 추적 HTML | 진행을 보여 주는 것. 질문·답을 받지 않는다 |
| dz-decision-tracker | 결정 기록 보관·미결 목록·PM 컨펌 요청 형식 | 컨펌 요청이 2건 이상이거나 선택지 비교가 필요하면 그 스킬의 채팅 형식(A)·B) 선택지 나열) 대신 이 스킬의 질문 페이지로 묻고, 확정되면 거기에 기록한다. **단, 결정할 사람이 지금 대화 중인 사용자 본인일 때만** — 창구는 내 맥 안(`127.0.0.1`)에서만 열려 다른 사람은 답할 수 없다. 다른 사람(PM 등)의 권한이 필요한 컨펌은 decision-tracker 형식으로 초안을 만들어 사용자가 전달하게 하고, 질문 페이지의 「채택」을 그 사람의 승인으로 처리하지 않는다 |
| dz-oneffice-writer 등 원피스 스킬 | 원피스 문서 발행 | 질문 페이지는 원피스로 발행하지 않는다(내 맥 안의 대화 도구) |
| dz-external-report | 외부 보고 어휘 | 질문 페이지는 사용자 한 사람과의 대화용이다 |

## 12. 명령 한눈에

| 명령 | 하는 일 | 종료 코드 |
|---|---|---|
| `new --spec 질문.json --out 페이지.html [--force]` | 1회차 페이지 만들기(점검에 걸리면 저장 안 함) | 0 · 1 |
| `check 페이지.html [--render] [--shots 폴더] [--json]` | 정적 점검 + 렌더 실측 | 0 통과 · 1 문제 · 3 렌더 못 함 |
| `serve --page 페이지.html --out 답.json [--timeout 초] [--port N]` | 창구. 첫 줄 접속 주소. `--out` 에 지난 답 파일이 있으면 `.old-{시각}.json` 으로 옮기고 시작 | 0 답 받음 · 2 시간 초과(마지막 줄 `TIMEOUT`) 또는 인자 오류(`fbq.py serve: error:`) · 1 시작 못 함 |
| `open --url 주소 --match 페이지파일명 [--dry-run]` | 같은 탭 주소 교체, 없으면 열기 | 0 |
| `read (--answer 답.json \| --text 붙여넣은.txt \| --text -) [--page 페이지.html]` | 답 → 구조화 JSON(`--page` 를 주면 그 페이지의 카드 번호로 읽음) | 0 · 1 못 읽음 |
| `append --page 페이지.html --spec 다음.json --answers 답 [--reflected 반영.json] [--force]` | 이번 회차를 표로 접고 다음 회차 붙이기. 붙여 넣은 답(원문·그 글을 읽은 `read` 출력)은 빠짐 의심(`loss_risk`·카드 수)이 있으면 거부. `--force` 는 회차·저장 키 불일치, 붙여 넣은 답의 빠짐 의심, 점검 실패를 모두 무시(확인한 뒤에만) | 0 · 1 |

파일로 직접 열어야 할 때(창구 없이)의 주소: `python3 -c 'import pathlib,sys;print(pathlib.Path(sys.argv[1]).resolve().as_uri())' "$P"` 의 출력을 `open --url` 에 준다.
