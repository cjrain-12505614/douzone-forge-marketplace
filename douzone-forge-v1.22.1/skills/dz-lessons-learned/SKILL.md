# Lessons Learned

프로젝트 진행 중 발생한 교훈과 패턴을 기록·활용한다.

## 교훈 기록 위치

| 위치 | 성격 |
|---|---|
| `CLAUDE.md` 「알려진 이슈 및 교훈 (현행 활성분)」 | 세션에서 자주 걸리는 현행분만 (전체 아카이브 아님) |
| `참고자료/리포트/` | 경위·실측 근거가 있는 진단 — **공용 사안** |

## R15 — 오진·사고일 때 (체크 항목 누적)

기록할 교훈이 **오진·사고 유형**이면(내린 판단이 사실과 달랐음이 드러난 경우 — 관측은 맞았는데 **귀속**이 틀린 경우 포함) 교훈 한 줄로 끝내지 않고 다음 3단계를 수행한다.

1. **그 도메인 SSoT 문서에 체크 항목 한 줄을 추가한다.** 「무엇을 먼저 확인했어야 했는가」를 다음 사람이 바로 쓸 수 있는 형태(**실행 명령·판정 기준**)로 적는다. 감상·반성 문장은 넣지 않는다.
   - 예(2026-07-30 실제 적용) — `참고자료/AI트렌드/INDEX.md` 「채번 규칙」 6번: 「원격과 동기화되지 않은 상태에서는 번호를 부여하지 않는다 · 항목이 안 보이면 유실로 단정하기 전에 `git log -1 origin/main`과 원격 도달 여부를 먼저 본다」
2. **경위·실측 근거를 기록한다** — 공용 사안은 `참고자료/리포트/`, 개인 운영 사안은 `_개인/sessions/`.
3. **재발 확인** — 같은 유형이 다시 나오면 1에서 넣은 항목에 실제로 걸리는지 확인한다. 걸리지 않으면 표현이 추상적이라는 뜻이므로 실행 가능한 형태로 다시 쓴다.

⛔ **1을 건너뛰지 않는다.** 교훈만 적고 체크 항목을 안 넣으면 다음 사람이 같은 자리에서 다시 넘어진다.

연계 — 연쇄 갱신 **R15**(`규칙/프로세스/연쇄-갱신-명확화.md`) · 강제원칙 **원칙 5**(가정 금지).

## 교훈 기록 시점

1. **PM이 수정/피드백을 주었을 때** — 즉시 기록
2. **에이전트가 잘못된 결과를 냈을 때** — 원인 분석 후 기록
3. **예상보다 잘 된 패턴을 발견했을 때** — 재활용을 위해 기록
4. **세션 종료 시** — 해당 세션의 교훈을 정리

## 기록 형식

```markdown
### YYYY-MM-DD
- {교훈 내용} → {방지/활용 규칙}
```

예시:
```markdown
### 2026-03-21
- 에이전트에게 "계획 세워서 확인 받아라" 하면 불필요한 대기 발생 → 프롬프트에 "바로 실행" 명시
- 기존 모듈 연동을 당연시 가정함 → 비즈니스 맥락은 반드시 PM에게 확인 후 진행
```

## 교훈 활용

- 에이전트 디스패치 시 관련 교훈을 프롬프트에 반영
- 새 세션 시작 시 `CLAUDE.md` 「알려진 이슈 및 교훈」을 읽어 반복 실수 방지
- 유사한 작업을 할 때 이전 교훈을 참고하여 접근 방식 조정


## 마크다운 링크 규칙 (필수)

마크다운 파일 작성·업데이트 시 **모든 경로·파일 참조는 클릭 가능한 상대 링크**로 작성한다.

```markdown
# 나쁜 예 (클릭 불가)
법무관리/tasks/_current.md에서 확인

# 좋은 예 (클릭 가능)
[법무관리/tasks/_current.md](../법무관리/tasks/_current.md)에서 확인
```

- 상대 경로는 현재 파일 위치 기준
- 코드블록 안의 폴더 구조 다이어그램은 예외 (링크 불필요)
- 상세 규칙은 douzone-forge CLAUDE.md의 "마크다운 링크 표기 규칙" 섹션 참조
