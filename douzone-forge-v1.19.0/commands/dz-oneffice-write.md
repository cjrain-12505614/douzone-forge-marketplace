# /dz-oneffice-write 커맨드

HTML 파일 또는 현재 대화 맥락을 원피스 워드 문서로 만들어준다.
새 문서 생성 → (선택) 단일페이지 전환 → HTML 주입 → 꺾쇠 정렬 → 문서명 변경 →
저장 → 검증까지 한 번에 실행.

## 사용 예

```
/dz-oneffice-write Amaranth10-forge-사용가이드.html
/dz-oneffice-write 오늘 회의 요약을 원피스 문서로 만들어줘
/dz-oneffice-write --long --title "2026 AI 위원회 3차 회의록"
/dz-oneffice-write --from ./report.md --title "주간 리포트"
```

## 옵션

| 옵션 | 설명 |
|------|------|
| `--long`, `--webpage` | 단일페이지 모드 (웹페이지형 긴 문서). 기본은 다중페이지. → 트랙 A `onepage=True` |
| `--paper A4\|A3\|B5\|LETTER` | 용지. 기본 **A4**. → 트랙 A `paper` (원시값 `"210,297"` 도 가능) |
| `--margin normal\|narrow\|wide` | 여백 — 보통 20mm(기본)·좁게 10mm·넓게 30mm. → 트랙 A `margin` |
| `--landscape` | 가로 방향. → 트랙 A `landscape=True` |
| `--title "..."` | 문서명 지정. 생략 시 `YYMMDD_새 문서`. |
| `--from <경로>` | HTML 또는 Markdown 파일 직접 참조. 생략 시 현재 대화 맥락에서 합성. |
| `--template minutes` | **회의록 템플릿(네이비 브리프형)** 강제 적용. 아래 「회의록 프리셋」 참조. |

> 용지·여백·단일페이지·가로는 **생성 시점에 확정**된다(트랙 A, 실측 2026-07-22) — 브라우저
> 문서설정 팝업을 열 필요가 없다. 트랙 B(브라우저 폴백)에서만 리본 → 파일 → 문서 설정으로 조작.

인자 없이 실행하면 현재 대화에서 "방금 만든 HTML/리포트/요약"을 찾아 사용한다.

## ⛔ 콘텐츠 원칙 — 사실 전용 + 인포그래픽 (모든 실행에 적용)

> 2026-07-06 확정: **md 파일(회의록·계획서 등 작업 기록)까지는 다각도로 자유롭게
> 작성해도 된다.** 그러나 이 커맨드로 **HTML→원피스 변환**을 실행하는 순간부터는
> 반드시 지킨다 — 자비스-사용자 소통 흔적(질의·비판적 검토·`_(확인 필요)_` 메타
> 서술)을 걷어내고 **확정된 사실만**으로 재구성하며, 흐름·비교·구성비처럼 시각화가
> 이해를 높이는 지점에는 **인포그래픽**을 삽입한다. 상세는
> `dz-oneffice-writer` 스킬의 「콘텐츠 원칙」 섹션 참조.

아래 「회의록 프리셋」의 "원피스에는 공유 가능한 사실만" 규칙은 이 원칙의 회의록
특화 사례다 — 회의록이 아닌 보고서·계획서 등도 동일하게 적용한다.

## 회의록 프리셋 (`--template minutes` — 회의록이면 옵션 없이도 자동 적용)

**작성 대상이 회의록이면(옵션 유무와 무관하게) 워크스페이스 표준을 반드시 따른다:**

1. **표준·골격 로드** — douzone-forge 워크스페이스에서 두 파일을 읽는다:
   - 표준: `규칙/프로세스/회의록-원피스-템플릿-표준.md` (구조 7블록·상태 칩 6종·색 토큰·발행 절차의 SSoT[단일 출처])
   - 골격 정본: `규칙/프로세스/템플릿/회의록-원피스-골격-네이비브리프.html`
2. **골격의 `{중괄호}` 자리만 실제 내용으로 교체** — 블록 순서(네이비 헤더 밴드 → 참석·목적 메타 → ⚡한눈 요약 → 01 배경 → 02 주요 논의 → 03 결정사항 → 04 액션 아이템 → [05 회의 후 확정 사항] → 푸터) 고정. 새 스타일 창작 금지.
3. **문서 설정 고정**: A4 · **단일 페이지** · **좁은 여백** — 트랙 A에서는 생성 파라미터로 지정한다
   (`paper="A4", onepage=True, margin="narrow"`). 트랙 B(브라우저 폴백)일 때만 문서설정 팝업 조작 +
   **모드 C 평면 주입**(꺾쇠 정렬 생략).
4. **결정·액션에 상태 칩 필수** (합의/진행 중/후속 확정/확인 필요/대기/완료 — 색상은 표준 §3).
5. **원피스에는 공유 가능한 사실만** — 내부 판단·STT(음성 자동 전사) 정제 노트·비판 검토는 forge 회의록 md에만 남긴다.
6. 문서명: `YYMMDD_{회의명}_회의록_PRJ-{코드}` (PRJ 미해당 회의는 코드 생략).
7. 참석자 소속은 **a10 라이브 조직도로 현재 조직 확인** 후 표기 (과거 문서의 조직명 복사 금지).

> 워크스페이스에서 표준·골격 파일을 찾지 못하면(비 forge 환경) 사용자에게 알리고 일반 절차로 진행한다.

## 실행 절차 — 2 트랙 (A10 직접 우선, 브라우저 폴백)

원피스 발행 경로는 두 가지다. **신규 발행은 트랙 A(A10 직접 호출)를 우선**하고,
아래 폴백 조건에 해당하면 트랙 B(브라우저 DOM 주입)로 내려간다.

> **왜 트랙 A가 기본인가**: a10 MCP `create_oneffice_doc` 도구(원피스 생성 API
> `one001A01`)가 **함수 한 번으로 문서 생성 + 본문(HTML) 주입 + 저장**을 끝낸다
> (라이브 실측 확정 2026-07-22, forge `참고자료/리포트/2026-07-22-A10원피스-직접생성-실측확정.md`).
> 브라우저 탭 확보·편집모드 전환·꺾쇠 정렬·저장 버튼 클릭·문서명 커밋이 **전부
> 불필요**하고, 저장 클릭 함정·읽기모드 no-op·체크아웃 경쟁이 **원천적으로 없다**.

### 트랙 선택 규칙

- **트랙 A (A10 직접 · 기본·권장)**: a10 MCP `create_oneffice_doc` 가용 + **새 문서 신규 발행**.
  용지(A4·A3)·여백(좁게·보통·넓게)·**단일 페이지**·가로 방향은 **생성 파라미터로 지정**되므로
  (실측 확정 2026-07-22) 회의록·`--long` 긴 문서도 **트랙 A로 처리한다**.
- **트랙 B (브라우저 DOM 주입 · 폴백)**: 다음 중 하나라도 해당하면 트랙 B.
  1. a10 MCP `create_oneffice_doc` 미가용(플러그인 갱신 후 코워크 앱 MCP 재기동 전·비 forge 환경)
  2. **기존 문서 재편집** — `one001A01`은 신규 생성 전용. 이미 있는 문서의 내용 수정은 DOM 경로(`one001A17`)만 가능

### 공통 1. 입력 정규화 → HTML 준비 (두 트랙 모두)

- `--from` 이 HTML이면 그대로, Markdown이면 HTML로 변환, 자연어면 대화 맥락에서 합성
- **콘텐츠 원칙 적용**(위 「콘텐츠 원칙」 — 사실 전용 + 인포그래픽) + **script/nav/button/form 제거**
- **인라인 스타일 + 화이트리스트 태그**(p·div·ul·ol·li·table·thead·tbody·tr·td·th·h1~h6·span·br·img·pre·hr 등)로
  평탄화 = `dz-oneffice-writer` **모드 C(평면 주입)** 형식. 이 HTML이 그대로 원피스 본문이 된다.
- **볼드는 `<b>`/`<strong>` 대신 `style="font-weight:bold"`** (재편집 저장 시 언랩 방지)
- 회의록이면 「회의록 프리셋」 골격으로 HTML 구성 (트랙 무관)
- **관련 문서(아마링크) 삽입** — 본문에 참고 문서를 '카드'로 넣을 땐 평문 URL 이나 `resolve_amalink` 의
  convertText 마크업(`|>@…@<|`)을 그대로 넣지 말 것(헤드리스 create·붙여넣기 모두 렌더 안 됨). **완성된
  `dze_amalink` 앵커를 HTML 에 직접** 넣는다 — 앵커 구조·빌더(`OF.amalinkAnchor`)와 `resolve_amalink` 로
  제목·`?token=` 공유링크 확보 절차는 [`dz-oneffice-kit`](../skills/dz-oneffice-kit/SKILL.md) §5. (트랙 A·B 공통)

### 트랙 A. A10 직접 생성 — `create_oneffice_doc` 호출

1. 준비한 본문 HTML·문서명·**문서 옵션**으로 a10 MCP 도구 호출:
   ```
   create_oneffice_doc(
     title="<문서명>", html="<인라인 스타일 본문 HTML>", folder_uid="",
     paper="A4", margin="normal", onepage=False, landscape=False, eager_images=True
   )
   ```
   - **문서 옵션 — 생성 시점에 확정된다**(브라우저 문서설정 팝업 불필요, 라이브 실측 2026-07-22):
     · `paper`: `A4`(기본)·`A3`·`B5`·`LETTER` 또는 `"가로,세로"`(mm) 직접
     · `margin`: `normal`(20mm 기본)·`narrow`(10mm)·`wide`(30mm) 또는 `"상,하,좌,우,머리말,꼬리말"` 직접
     · `onepage`: `True` = **단일 페이지**(웹페이지형 긴 문서 — `--long`/`--webpage` 대응)
     · `landscape`: `True` = 가로 방향
   - `folder_uid` 비우면 내문서함 루트(`PR_ROOT`). 특정 폴더 저장은 `list_onechamber_folders`로 폴더 UID 확보 후 전달
   - **HTML은 `<dze_doc_property>` 래퍼 없이 순수 본문만** — 도구가 문서 옵션으로 자동 생성·부착한다.
     이전 판 HTML을 재사용해 `<dze_doc_property>`가 섞여 들어가면, 옵션을 명시한 경우 **도구가 교체**하고
     결과를 응답 `docProperty`에 표기한다(2026-07-23 개선 — 종전에는 조용히 무시되어 여백이 안 먹었다)
   - **본문 폭은 지정하지 않는다** — 폭을 안 주면 지면을 정확히 채운다(12조합 전건 실측 2026-07-23).
     `width:1047px !important` 같은 픽셀 고정은 불필요하고 인쇄·PDF·배율에서 깨진다.
     글 영역 = 용지 − 좌우 여백: A3 좁게 **1047** / A3 보통 971 / A4 좁게 718 / A4 보통 642 px.
     **폭이 좁아 보이면 폭을 강제하지 말고 `margin` 설정을 먼저 확인**한다
   - **이미지는 즉시 로딩** — `eager_images=True`(기본)가 `loading` 없는 `<img>`에 `loading="eager"`를
     자동 부여한다. 편집기가 미지정 `<img>`에 `lazy`를 붙여 **외부 주소 이미지가 화면에 안 뜨는** 문제를
     막는다. 영구 보존이 필요하면 **내장 base64**(본문 4MB까지 실측 확인). PDF 출력은 서버 렌더라
     지연 지정과 무관하게 이미지가 모두 나온다 — 화면 열람 한정 문제다
2. 반환 `{resultCode, resultData:{fileUID, docUID, editorUrl, folderUID, name, docProperty, eagerApplied}}` 확인.
   `resultCode ≠ 0` 이면 `resultMsg` 확인 후 **트랙 B로 폴백**.
3. **생성 후 편집기를 크롬으로 항상 연다** — `editorUrl` 을 브라우저로 열어 사용자가 결과를 바로 보게 한다.
   ⚠️ **추가 검증(스크린샷 판독·본문 재조회)은 매번 하지 않는다** — 생성 API가 저장까지 확정하므로
   불필요하다(2026-07-22 차민수 수석 지시). 사용자가 확인을 요청하거나 이상 징후가 있을 때만 검증한다.
4. 삭제가 필요하면 `delete_oneffice_doc(doc_uid=<docUID>)`.

### 트랙 B. 브라우저 DOM 주입 (폴백 · 기존 절차)

1. **빈 문서 탭 확보** → 스킬 `dz-oneffice-new-doc-opener` (기존 빈 `.onex` 탭 있으면 재사용, 편집모드 진입 확인)
2. **(옵션) 단일페이지 전환** — `--long`/`--webpage` 시 리본 → 파일 → 문서 설정 → 페이지 분리 → "단일 페이지"
3. **HTML 주입 → 정렬 → 문서명 → 저장** → 스킬 `dz-oneffice-writer`
   (writer Step 1.9 편집모드 가드 → 3~5 주입+정렬 → 6 문서명 → 7 저장+새로고침 검증)
4. **읽기모드 전환 후 스크린샷 반환**

## 치명적 주의 — 트랙 B(브라우저 DOM 주입) 한정

> 아래 함정은 **모두 브라우저 DOM 주입(트랙 B) 경로의 것**이다. **트랙 A(A10 직접
> 생성)는 브라우저 배관을 거치지 않으므로 이 함정들이 해당하지 않는다** — 저장은
> 서버가 처리하고, 편집모드·`.dze_page_main`·`.onex` 확장자 문제가 발생하지 않는다.

- **저장 전 새로고침 금지.** writer Step 7 순서를 절대 뒤집지 말 것.
- **편집모드 가드 필수.** 읽기모드에서 저장은 silent no-op.
- **`.dze_page_main` 직접 수정 금지.** 모든 스타일은 자식 요소 인라인으로만.
- **읽기모드에서 점선(dashed outline)이 보이면** ONEFFICE 가 블록 요소에
  `outline: 1px dashed` 를 자동 주입한 것. writer 의 Step 4 Python 스니펫과
  Step 8 JS 주입으로 `* { outline: none !important; }` 를 삽입해야 한다.
  즉시 수정: Step 8 JS 스니펫을 편집모드에서 실행 후 재저장.
- **반드시 `.onex` 로 생성된 탭을 사용.** 일반 navigate 나 "새 문서" 버튼은
  `.noext` 를 만든다. opener 스킬 또는 "ONEFFICE 워드" 템플릿 버튼 경유 필수.
  저장 후 홈 화면에서 확장자 육안 확인 (Step 10.5).
