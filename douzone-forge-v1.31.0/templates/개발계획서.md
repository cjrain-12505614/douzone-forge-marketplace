## 0. 목적 · 작성 원칙

### 목적 (왜 쓰는가)

1. **개발 착수 기준** — 코딩 전, 무엇을 어떤 순서로 얼마나 들여 언제까지 만들지 합의
2. **개발 관점 정리** — 기획/설계 산출물을 개발 시각(영향 범위·기술 제약·재사용·리스크)으로 재독
3. **공수·일정 근거** — 재현 가능한 공식(PERT·CPM)으로 산정 → 일정 협의·자원 배분 근거
4. **추적성** — 요구사항(REQ/AC)·화면(SCR)을 개발 Task(TSK)로, Task를 개발설계 산출물로 연결
5. **자동화 입력** — 구조화 필드(부록 B)로 자동화 체계(스킬·도구)가 공수·일정을 그대로 계산

### 작성 원칙 5

명확성(한 Task=한 작업) · 완전성(누락은 `_(확인 필요)_`) · 의존성 정합(순환 없음·위상 정렬 가능) · 산정 재현성(공수·일정은 공식대로, 임의값 금지) · 추적성(REQ/AC·SCR↔TSK↔개발설계 항목)

> 작성 절차: 입력 수집 → 개발 관점 분석 → Task 분해·의존성 → 공수 측정 → 일정·마일스톤. 비강제(작성 여부 선택) + 작성 시 형식 정합 MUST.

## 5. 공수 측정 (PERT — 단위 인일)

| Task | O | M | P | TE=(O+4M+P)/6 | σ=(P−O)/6 | TE'=TE×k |
|------|---|---|---|---------------|-----------|----------|
| TSK-01 | | | | | | |
| TSK-02 | | | | | | |
| TSK-03 | | | | | | |
| **합계** | | | | **Σ TE** | | **Σ TE'** |

> k = 보정계수(실측 누적 `Amaranth10/{모듈}/tasks/_공수실측.md`. 표본 0이면 1.0). 임계 경로 불확실성 σ_total = sqrt(Σσ²|임계경로). 90% 상한 ≈ 임계경로 합 + 1.645×σ_total.

## 6. 일정 · 마일스톤 (CPM)

> **투입 인원·가용성·자원 배치(협업 기본)**: 투입 개발자 수와 Task별 담당자(§4)를 먼저 정한다(Cell리더 배분). 각 개발자의 **전 프로젝트 task 부하(가용성)**를 먼저 확인해 가용 시점부터 배치(모든 PRJ TASK·WBS 기준). **공수(인일)≠일정(달력)** — 같은 담당자 Task는 직렬, 다른 담당자는 의존성 범위에서 병렬. 1명이면 일정=Σ TE'(직렬), N명이면 ≥ 임계경로. 아래 표 위에 투입 인원·배치·가용성 가정을 명시. (예: "개발자 2명 — A: TSK-02, B: TSK-03 병렬")
> **WBS 제안 → 확정**: 이 일정표(WBS)는 **제안**이며, 실무 개발담당자 또는 리더(Cell리더) 의견 수렴 후 확정한다(문서 상태 = 제안/확정).

### 6.1 임계 경로 (의존성 최단)

| Task | ES | EF | LS | LF | slack | 임계? |
|------|----|----|----|----|-------|------|
| TSK-01 | | | | | | |
| TSK-02 | | | | | | |

> ES=max(선행 EF), EF=ES+TE'. LS=LF−TE', LF=min(후행 LS). slack=LS−ES. 임계 경로 = slack 0 사슬. 총기간 = max(EF).
